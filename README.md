# software · 第二十届全国大学生软件创新大赛参赛项目

> 赛题1「AI 赋能学习生产力 —— 面向移动终端的场景创新」
> 参赛单位：**中南大学** ｜ 团队：**计算机科学与技术 × 3 ＋ 文学院 × 1**（队长＝计算机科学与技术）
> 官网：<https://www.swcontest.com.cn> ｜ 主题「软件定义世界，创新引领未来」

## 项目概念

**StudyFlow 智学伴侣** —— 跨设备协同的大学生 AI 学习伙伴。
把手机随身采集、平板手写整理、PC 深度创作打通，让 AI 贯穿
**采集 → 理解 → 积累 → 复用 → 反馈** 的完整闭环，且任务状态跨设备不丢、用户始终保有三权（知情权 / 选择权 / 控制权）。

聚焦赛题1 的三个互补方向：**方向1 移动记录 + 方向2 个人学习资料 + 方向6 多设备协同**（记录与接续壳）。

**内核升级**：在此之上补齐「课程模块 + 知识图谱 + 错题本」的适应性学习内核——五层架构、三个核心数据对象（知识点 / 题目 / 错题·掌握度）、苏格拉底四步辅导、四级作业模式 A–D、可解释出题权重公式（**v0.2 降为待商量草案，新增「用户意愿优先·权重兜底」两层**）、语音/视频（**后置为最后待办**）、课程模块（**分两步**）/学习计划表，8 步 MVP 按 P0/P1/P2 分阶段落地。完整规格见 [`产品功能规格_赛题1.md`](产品功能规格_赛题1.md)。
团队本身就是「理工材料 vs 人文材料」的天然对照样本（计科的代码/公式/英文技术文档 ↔ 文学院的古籍/引文/手写批注/双语资料）。

## 目录结构

> **整理口径（2026-11-07，二次清理后）**：文件平铺在根目录、按前缀分类，`demo/` 为可运行原型子目录。
> 这样安排是为了让各文档里「本目录《…》」「附件4」「按附件7模板」「`demo/index.html` 双击可跑」这类互引与操作路径保持**可直接照做**——若改成多层子目录，会连锁破坏 demo 运行与大量「照着做」的路径。
> 已清理：① 2 个 git 初始历史遗留的测试垃圾文件（`readme.text` / `readme.txt`）；② 架构图构建中间产物目录 `.archify/`（含 1 份与交付版重复的 HTML、4 张截图、5 份校验 JSON —— 交付版 [`软件工作流程架构图_赛题1.html`](软件工作流程架构图_赛题1.html) 已自包含全部内容，源规格另存为 [`架构图源规格_赛题1.json`](架构图源规格_赛题1.json) 以便复现/改图）；③ 误产生的 0 字节 `NUL` 文件。其余文件均为有效交付物，无旧版残留。

## 快速预览 Demo

```bash
# 零依赖、零构建、零联网，直接双击 demo/index.html 或用浏览器打开
start demo/index.html        # Windows
```

- 右上角 **「一键演示闭环」**：自动走完 采集 → 理解 → 积累 → 复用 → 反馈
- 右上角 **「场景」按钮**：在「计算机科学与技术 ↔ 文学院」间切换，验证异质材料适配
- `demo/js/adapters.js` 是唯一边界：5 个 Mock 适配器（ASR / OCR / LLM / RAG / 跨设备）。
  W3 技术 Spike 定下端侧 vs 云端方案后，由 A 替换真实实现，界面代码无需改动。
- 详见 [`demo/README.md`](demo/README.md)

> ⚠️ Demo 是 **W1 脚手架**，AI 能力全为桩函数、无真后端、刷新即重置；量化数据待 W4–W11 真实试用补齐。`adapters.js` 是唯一边界：W3 技术 Spike 后由 A 扩 MockLLM（苏格拉底/出题/作业分级）并替换真实实现，B 界面代码不改（详见功能规格第11节）。
